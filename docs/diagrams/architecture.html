How brief2motion works

One loop for every site: route, spec, build, check, fix, deliver. The checks run in a real Chrome on your machine.
1
Route
Reads the brief and proposes a motion stack and a visual style, quoting the words that led there.
route.mjs
2
Spec
Design plan, motion plan (load, scroll, input), exact copy, and a "done when" list that can be checked.
SPEC.md
3
Build
Starts from the closest example, the shared kit and the reference for that stack and style.
site/
4
Check
Frame time on desktop and an emulated phone, three widths, reduced motion, keyboard, contrast, no WebGL, no JavaScript.
check_site.mjs
5
Fix
Fixes the page, never the budget, and measures again. Then looks at the screenshots.
check/shots/
6
Deliver
A localhost link to the page and a report with the proof behind every line of the brief.
REPORT.md
fails a check? fix and measure again

The stacks it chooses from

three.js, React Three Fiber3D products, exploded views, shaders
Dust engineparticles that form a product, face or word
View Transitions APIpage to page, and grids that rearrange
SVG and D3 scalescharts and lines that draw themselves
Lottie and Riveanimation files from a designer
32 visual stylestokens, tested CSS and accessibility notes for each
Fundamentalshierarchy, type, contrast, Core Web Vitals
