Orientationbrief2motion 1.1.0
What you can build
brief2motion is a skill for Claude Code and Codex. You describe a website in plain words, and the agent builds it with motion that suits it, then measures the result in a real browser before you see it.
This guide is for people who can describe what they want and would like to understand what they get back: founders, designers, marketers and developers. It explains how to write the brief, how the skill chooses its tools, what each tool is good at, the visual styles it knows, and what the checks mean. Every example in it is in the repository and runs on your machine.

How it works: one loop for every site
Whatever the brief asks for, the agent goes through the same six steps. The fourth is the one that matters: the page is measured, and a failed check is a fix, not a footnote.
The loop, and the stacks the first step chooses from.

What you can read afterwards

A design plan, a motion plan in three lists (on load, on scroll, on input), every word of copy, and a "done when" list.

Fixes the page, never the budget, and measures again. Then looks at the screenshots.

Two ideas hold the loop together. The first is that a brief ends in things that can be checked, so "done" is a list of numbers and screenshots instead of an opinion. The second is that the page has to work for everyone who opens it: on a small phone, with a keyboard, with motion switched off, without WebGL, even with JavaScript off.

The first stepbrief2motion 1.1.0
Routing: how the stack and the style are chosen
The router is a keyword scorer with a rule book you can read. It has never seen your product, so the agent treats its answer as a proposal.
The stack
Each stack has a list of phrases with weights. The stack with the highest total wins, and the default is the lightest one. A few rules keep it honest:
The default is no library. "Something should move" is not evidence for GSAP or three.js. Reveals, hovers and a pinned scene are plain CSS and JavaScript.
React changes the answer. 3D in a React project goes to React Three Fiber, and interface motion goes to Motion for React. Both come with a note that they need your project's bundler.
Fallback requirements are not requests. "It must still read without WebGL" does not route to three.js.
A named library wins. If the brief says GSAP, it is GSAP.
The style
A style named in the brief is used. Otherwise the router looks at what the product is, who it is for and the mood words, and one stray word is never enough: "paper" in "paper plane" does not pick a paper-textured look. The first rows of the audience table:

The first stepbrief2motion 1.1.0
Site mode: a whole site, or a page that must convert
Some briefs ask for more than a page that moves. They ask for a site with several pages, or for one page that has to make a visitor do something. For those, brief2motion works through nine stages. Each writes one short file that you and the agent can both read, and each has a check.
When to use it
Use site mode when the brief asks for a site with several pages, or for one page whose job is to get a visitor to sign up, buy, book or register. Stay with the six-step loop when the motion is the point of the page: a product to turn, a scroll story, a particle portrait.
Site mode puts design before motion. Stages 1 to 5 come before the loop's first step. Stage 6 holds the routing and the spec. Stages 8 and 9 are the loop's build and check.

A one-page brief
A small brief does not need nine long documents. For a one-page site, keep one short entry in each file. You may skip stage 4 when the page has no template choice, and stage 7 when it has no motion. A site with several page types writes one entry per route or template.
Never skip stages 1, 2, 3 and 9. Without them nothing says what the page is for, whether its words are true, where it sits, or whether it worked.
The five checks
Five checkers write into one file, check/qa.json. Each record names the page, the state, the width, the browser, what was measured and the threshold. Beside them, build_tokens measures the colour pairs and check_site still runs the motion, fallback and weight checks.

The second reader
A checker measures. It cannot see that a layout is dull or that the first screen says nothing. So the last part of site mode is a second reader: a different agent or a person who did not build the page and has not read the brief. They get what a visitor gets, the built site and its screenshots, and write notes in REVIEW.md.
They start with three questions, answered cold from the first screen at 390 px and again at 1440: what does this page offer, and to whom; what did your eye land on first; what would you do next. Then they read the brief. Wherever their answers differ from what the brief meant, that is a finding, even if every check passed.
Three short tests follow. Switch to reduced motion and mute the tab: is the page still complete? Use it one-handed on a phone: can a thumb reach the main action? Shrink the first screen to 480 px wide: can you still say what it offers? Two rounds of fixes are enough. A third means the brief is unclear, and the question goes back to the owner.
Worked case: Larkspur
examples/larkspur/ is a 3-page launch site for a shared inbox, built through the nine stages, all but the second reader's notes. Larkspur is a made-up product, and the site says so near the top and in the footer. Its brief gives the facts it may state, two plans and a 14-day trial, and says there are no customers, logos, reviews or statistics. So the site has none. The brief's "done when" asks for a visitor on a phone to get from the home page to a finished trial form, including after one mistake.
larkspur, home page. One idea (the inbox drawn in code, marked as sample data), one action, and no invented proof.
The stage files are the content of the folder: 3 routes in routes.json, 11 sourced claims in CONTENT.md, 3 journeys in journeys.json, and one script that runs everything.
The script is examples/larkspur/tools/run-checks.sh. It runs those commands in stage order, keeps qa.json and site-report.json beside the example, and exits 0 when nothing failed. The default stack: plain CSS and JavaScript, with the kit
Most motion on a website needs no library. The kit is ten small files that handle the parts that are easy to get wrong.
File
What it does
kit.css
the accessibility floor: a skip link, a focus ring that shows on any background, the reduced-motion rule
motion-core.js
the reduced-motion switch, the state signal, frame loops that stop when hidden, one shared scroll listener, scroll progress for pinned scenes, and the maths
reveal.js
entrances with the Web Animations API; content stays visible if the script never runs
split-text.js
a heading cut into words, characters or lines, still read as one sentence by a screen reader
counter.js
a number that counts up while its real value stays in the page
svg-draw.js
lines that draw themselves
image-sequence.js
numbered pictures scrubbed on a canvas, loaded coarse to fine
view-transitions.js
same-page transitions and the shared element between pages
three-stage.js
a three.js renderer that fails softly, caps its pixel ratio, pauses off screen and holds one frame for reduced motion
players.js
Lottie and Rive, loaded only when needed and paused when unseen
A pinned scene with no library
Make the section tall and its child sticky. The kit turns scrolling into a number from 0 to 1 and writes it to a CSS variable.
Scroll-driven animation with no script at all
CSS can tie an animation to scroll position. sprout fills its pots this way. Browsers without the feature, and visitors with reduced motion, see the finished state.
Every page reports its stateA page ends its setup with signal('ready'), signal('reduced') or signal('static'). The checker waits for it, and CSS can style on it. "Static" means something the motion needs is missing and the page fell back to a still.
Stacksbrief2motion 1.1.0
GSAP, ScrollTrigger and Lenis
For choreography: several things moving in a set order, scenes pinned and scrubbed by scroll, sideways galleries, text that splits and sets.
All of GSAP is free since 2025, the former paid plugins included. It is free under GSAP's own licence, not an open-source one: it allows commercial work and code an AI wrote, and forbids use inside no-code animation builders that compete with Webflow. Pages load it from a CDN at a pinned version with integrity hashes.
tidewater: the section is pinned; the caption and the picture follow the scroll.
One frame for every page
gsap.matchMedia() owns every branch. Motion is created only inside it, and GSAP undoes all of it when a condition stops matching.
scrub: true for things that must stay locked to the scroll; scrub: 0.5 for things that should glide.
A pin of 200 to 300% of a screen is enough for one idea. Longer, and people think the page is stuck.
Sideways sections on wide screens with motion on; a normal swipe row otherwise.
Lenis stands down for reduced motion by itself. Give in-page links anchors: true, or they stop working.
Stacksbrief2motion 1.1.0
Motion, for plain pages and for React
Motion is the library that used to be Framer Motion. Use it for how an interface feels: springs, gestures, layout changes, things entering and leaving.
relay: the headline sets word by word; an amber block wipes in behind two words.
mise: a React planner. Rows make room when you drag; ticking moves an item between lists.
On a plain page
In React
Three things learned while building mise, each now in the reference:
A reorderable list tracks rows by value. Objects made during render look new every time and the order never changes. Pass ids.
A reorderable row is also a keyboard stop: Space picks it up, the arrow keys move it, Space drops it. Say so in its label.
Motion in an interface answers input. If nothing was pressed, nothing moves, and with reduced motion the same changes happen at once.
Stacksbrief2motion 1.1.0
three.js and React Three Fiber
For a real 3D object or scene: a product to turn, parts that come apart, a camera that travels, a shader.
The exploded view: each part sits in its own group and moves along one axis.
Colourways: a button repaints the enamel; a slider turns the radio for keyboard users.
What the kit's stage does for you
returns nothing instead of crashing when WebGL is missing, so the page can show its still picture;
caps the pixel ratio at 2 (a phone at 3 would draw nine pixels for every one);
sizes itself from the canvas, pauses when hidden or off screen, recovers from a lost context;
with reduced motion, draws one frame and holds it until something changes.
Light without files, a model without a file
A generated room, blurred into an environment map, gives enamel and brass something to reflect with nothing to download. A plane with a soft dark gradient under the object reads as a contact shadow and costs almost nothing. The radio itself is about forty primitives. For a real model the reference covers glTF, compression and credits.
Scroll poses
Describe each pose as plain numbers (camera angle, distance, how far the parts are pulled apart), give each a scroll position, and interpolate, holding each pose for a while before travelling. With reduced motion the scene cuts from pose to pose.
React Three Fiber needs a bundlerThe same scene can be written as React components with React Three Fiber and drei, and the reference shows how. Its renderer must match the installed React version exactly. A bundler takes care of that; a page that loads modules from a CDN cannot. The test page in the repository pins the versions by hand for that reason.
Stacksbrief2motion 1.1.0
The dust engine
The one stack with a complete template: you change a settings file and the engine does the rest.
copper-no-7: 60,000 dots form the bottle as the page loads.
Each dot has a place in a slow galaxy of dust and a place in each shape. Two numbers drive everything: how far the dust has formed, and which shape it is forming. The graphics chip moves every dot, so sixty thousand cost about the same as six hundred.
Stipple places dots by darkness and suits products and logos. Halftone puts round dots on a grid, sized by darkness, and suits faces. A portrait needs a calm, front-facing photo on a plain background.

Stacksbrief2motion 1.1.0
Page transitions with the View Transitions API
The browser takes a picture of the old page and morphs it into the new one. You write CSS and almost no script, and a browser without the feature changes the page the ordinary way.
halvorsen: four posters on the index.
A project page. The poster on the left is the one that was clicked: it grew into place.
On the index only the clicked card may carry that name, so a few lines of script set it as the old page leaves and again when you come Back. That script has to run before the page's first frame:
Without blocking="render" the first navigation after a fresh load showed no morph in testing. The smoke test now checks that both halves of the morph exist, in both directions.
Keep the two elements the same shape. A 4:5 poster into a 4:5 poster is clean.
One travelling element per navigation, and under about 600 ms: page changes are frequent.
For filter, sort and tabs on one page, wrap the change in document.startViewTransition and give each item its own name.

SVG, charts, Lottie and Rive
Three ways to move illustration. SVG in code is the lightest. Lottie plays an animation exported from After Effects. Rive plays an interactive animation with states.
keeling: the line is revealed by widening a clip, so it always ends exactly on the right year.
sprout: the stem draws, then seven leaves grow from the points where they meet it.
A line that draws itself
Measure the real length with getTotalLength(), set the dash to it and move the dash offset from that length to 0. Do not use pathLength="1" and do not combine a drawn line with vector-effect: non-scaling-stroke.
Charts
Write the SVG yourself and use D3 only for the maths: scales, and the path of a line. A chart needs a text alternative: a label that states the finding, a caption with the source, and the numbers in a table. Every number in keeling comes from one public file, and the page links to it.

The kit loads a player from the CDN only when the first animation is near the screen, plays it only while visible, and shows one chosen still frame with reduced motion. Reserve the box with aspect-ratio, so nothing jumps when the animation arrives.

Designbrief2motion 1.1.0
Design fundamentals: what every page gets
Motion sits on top of a page. If the page under it is hard to read, badly spaced or slow, no animation rescues it.
Say what it is, at the top
The first screen states what the product is and what to do next, with real content. People spend 57% of their viewing time above the fold and 74% in the first two screens (Nielsen Norman Group, 2018), so the first screen must not be a slow reveal of nothing.
Type and space
Body text 16 px or larger. Line length 45 to 90 characters. Line height about 1.5 for text, 0.95 to 1.15 for headlines.
A scale of four or five sizes, not a pile. Fluid headlines with clamp() and a rem floor.
Usually a single family; a second only when it contrasts plainly with the first. System fonts unless the brief supplies one.
Spacing in steps of 4 px. Group with space before lines.
Colour and contrast
Text contrast at least 4.5:1; large text 3:1; control edges 3:1. The thresholds are not rounded.
A palette is four to six named colours, with the text pairs checked before any CSS is written.
Light mode is the safer default. Research says it reads better for most people; default to dark only when the audience expects it.
Responsive, and fast
Design for 320 px wide first. Tap targets at least 24 px, 44 for anything primary. Never disable zoom.
Main content visible within 2.5 seconds, a tap answered within 200 ms, layout shift 0.1 or less (Google's Core Web Vitals).
Text hidden until an entrance animation runs is late content. Render it visible; animate from a readable state.
Give every picture, canvas and player a size, and animate transform and opacity, so nothing jumps.

Every animation has a job: point the eye, explain a change of state, or show where an element came from or went. Spend the motion budget on one planned entrance; when every block fades up and every card lifts on hover, nothing stands out and the page looks machine-made. Brief feedback to a visitor's own action is always worth animating.
Never invent proofNo made-up reviews, ratings, customer names, logos or numbers. If the brief has none, the section is left out. Made-up examples say that they are made up.

Web motion sits on a design, so the skill knows the major visual styles. Each was checked against a published source, and each has tokens, tested CSS, the motion that fits, its accessibility traps and when to choose it.
The 28 looks are live on one page in the repository, examples/style-atlas/: the same small product fragment in every style, so they can be compared and measured. The pictures on the next pages are screenshots of it. The atlas, the reference pages and the router are generated from one data file, so they cannot drift apart.

How to use a style
A style is a starting point for the look, never a reason to ignore the brief. Your colours and type replace its tokens.
Take the signature rules, not the specimen. Neubrutalism is thick borders, hard shadows and loud flat colour; it is not that particular yellow.
Read the accessibility list first. Several styles are defined by a property that fails contrast unless you compensate.
Spend the boldness in one place. A neubrutalist page with glass panels and a neon glow is three styles and no design.
Tools, not styles
Organic / blob shapes. Soft, irregular shapes made with an eight-value border-radius, an SVG path or clip-path. A tool used inside other styles (claymorphism, Corporate Memphis), not a documented style of its own.
Monochrome. One hue in several tints and shades. A palette decision used inside Swiss, minimal or dark-first work, not a style of its own.
A name that is not a style
Spectromorphism. Not a design style. No design source uses it; the nearest real word, spectromorphology, is a term from electroacoustic music. If a brief asks for it, ask whether neumorphism, skeuomorphism or glassmorphism was meant.

Glassmorphism, Liquid Glass-inspired
Surface styles
Glassmorphism
Frosted panels: a see-through fill, a blur of whatever is behind, a thin light edge and a soft shadow, floating over a colourful background.
Choose it for
Navigation bars, overlays and cards over pictures or gradients.
Avoid it for
Long reading text, data tables, low-end devices.
Signature rules
Fill about 15 to 40% opaque; a dark tint keeps white text readable when a bright shape drifts behind it

A 1 px light border and a soft drop shadow to lift the panel
Needs something colourful behind it, or there is nothing to frost
Motion that fits
Slow drift of the shapes behind the glass, and a small lift on hover. Keep the blur radius fixed: animating blur is expensive.
Accessibility
Text over a see-through panel has uneven contrast: test against the lightest and darkest thing that can sit behind it

An ancestor with opacity, filter, mask or clip-path limits what the blur can see

Named and popularised around 2020 to 2021; assessed by Nielsen Norman Group in 2024.

Liquid Glass-inspired

Choose it for
Media and photo products, Apple-platform companions, floating toolbars.
Avoid it for
Text-heavy pages, anything where the glass would sit on the content itself.

Glass only on the floating layer: bars, buttons, sheets

Springy scale on press, and controls that merge or split. Keep it to the control layer.

Surface styles
Neumorphism (soft UI)
Shapes pushed out of, or pressed into, a surface of the same colour, drawn only with one light shadow and one dark shadow.

Inflated, toy-like shapes: very round corners, two inner shadows that model the form, and one big soft coloured shadow underneath.

Children and education products, playful consumer apps, onboarding screens.
Avoid it for
Finance, legal, anything that should feel sober.

Dark-mode-first
The dark theme is the designed default: near-black surfaces in a few elevation steps, soft white text, one bright accent.
Choose it for
Developer tools, media and video, games, dashboards used in dim rooms.
Avoid it for
Long-form reading for a general audience, unless a light theme is one click away.

Background near black, not pure black; text off-white, not pure white
Depth from lighter surfaces, not from shadows
Accent colours less saturated than on white
Ship a light theme too, switched by prefers-color-scheme
Motion that fits
The same as the light theme. Glows and gradients read stronger on dark, so use less.
Accessibility
Light mode performs better for most people in most conditions: offer both and respect the system setting
Pure white text on pure black causes halation for some readers
Borders need 3:1 against the surface to be seen
Origin
A practice, not a movement. Research from Nielsen Norman Group says light mode reads better for most people, so a dark default needs a reason.
Visual treatments
Isometric
Objects drawn as if seen from above at an angle with no perspective, so parallel lines never meet. Reads as a tidy little model world.
Choose it for
Explaining systems, infrastructure, logistics, fintech flows, feature diagrams.
Avoid it for
Emotional or lifestyle brands.
Signature rules
Three visible faces per object: top lightest, one side mid, one side darkest
True isometric uses 30° to the horizontal; pixel-friendly art uses a 2:1 slope
One light direction for every object
Flat colours; depth comes from the three tones
Motion that fits
Parts lift, stack and slide along the three axes. Layers separating vertically explain how a product is built.
Accessibility
Isometric scenes are illustrations: describe what they show in text
Small isometric labels get hard to read at an angle; keep text flat
Origin
A technical drawing projection; familiar from games, which usually use a 2:1 pixel ratio.

Accessibility: the page works without the motion
Some people get dizzy or nauseous from movement on a screen, and they tell their system so. Others use a keyboard, a screen reader, or a browser where a script failed. The page has to work for all of them.
Reduced motion
No travel across the screen, no parallax, no zoom, no rotation, no loop that plays by itself.
The finished state is on screen: the headline is set, the line is drawn, the shape is formed.
Things that change with scroll may still change, in cuts instead of travel.
Normal scrolling works.
Library
How it honours the setting
GSAP
motion is created only inside gsap.matchMedia() for visitors with no preference
Lenis
on by default: no smoothing, instant programmatic scrolls
Motion for React
<MotionConfig reducedMotion="user"> turns transform and layout animation off
three.js
draw one frame and hold it; draw again only when something changes
Lottie, Rive
load paused on a chosen still frame
View Transitions
the opt-in rule sits inside a media query for visitors with no preference
Without the script, without WebGL
Content is in the HTML, and visible by default. Something is hidden for an entrance only by a script that is already running.
Every WebGL canvas has a still picture standing by, shown when the context cannot be created, a library fails to load, or an error is caught.
A blocked CDN leaves a complete, still page.
Keyboard and screen readers
Everything that works with a pointer works with a keyboard. A drag needs another way: a slider, arrow buttons, or a built-in keyboard grab.
A visible focus ring on every control. A skip link first, and the content inside a main landmark.
Split text keeps one readable sentence. Decorative canvases are hidden from assistive technology; meaningful ones have a label.
The result of an action is announced in a live region, not shown by motion alone.
A floor, not an auditThe checker verifies these mechanically. That catches the common failures. It does not replace testing with a screen reader and with real people.

Rules that keep frames short
Animate transform and opacity. They are composited without layout or paint.
One read and one write per frame. Measuring layout after writing a style makes the browser lay out again.
Stop what cannot be seen: loops pause when the tab is hidden and when their element is off screen.
Do not animate a blur radius or a full-screen filter. Blur a picture once, then move it.
On a 3D canvas, cap the pixel ratio at 2, light with an environment map and one light, and keep post-processing off the phone tier.

What a checker cannot see
It cannot see that a layout is dull, that a headline says nothing, or that text sits on a busy picture: text over pictures, gradients and canvas has no single background colour, so its contrast is not measured. After the checks pass, the agent opens the screenshots and looks at them against every "done when" line. So should you.
What the checker found in its first week
In the version 0.2 template, the brand link was 20 px tall, and the navigation bar kept fading for 1.1 seconds when a reduced-motion visitor scrolled. Both are fixed.
Five styles in the atlas had button text below 4.5:1. See-through panels were being measured as if they were solid, which was a fault in the checker itself; it now blends them first.
A helper line faded to 86% opacity failed "all text visible". The fade was removed.
Three layers of tests
Unit tests cover the router, the kit's maths and the measuring code. A smoke test per stack opens the real example and proves the documented pattern does what it says: the poster really morphs between pages, keyboard reorder really moves the row, the canvas really changes with scroll. Then the full check runs on every example.

Troubleshooting and questions
Symptom
Cause and fix
The page is blank
You opened the file, not the address. Run serve.py and open the link it prints.
"Could not start a browser"
Install Chrome, or run npx playwright@1.65.1 install chromium, or set BRIEF2MOTION_CHROME.
"The page never set data-motion"
The page did not report its state. Call signal() from the kit when setup is done.
The frame-time check fails
Usually layout properties being animated, an uncapped pixel ratio on a 3D canvas, or a loop running off screen. On a machine with no GPU, pass --no-perf.
The reduced-motion check fails
Something still moves, or some text never becomes visible. Check each library's own switch.
Sideways scroll at 320 px
The report names the element. Usually a row that does not wrap, or a grid track without minmax(0, 1fr).
The weight check fails
Pictures about 1200 px wide as WebP with a 720 px copy; a sequence about 960 px wide at quality 60 to 70.
A dust portrait does not look like the person
A calm, front-facing photo from the shoulders up on a plain background, with halftone and an oval mask.
Questions
Does it cost anything? The skill is free and MIT licensed. The agent runs on your own Claude Code or Codex plan, and the checks run on your machine.
Does it upload my files? No. A built page loads its libraries from one CDN when a visitor opens it, and the first check downloads a browser driver once.
Which frameworks? A plain static site is the default and the best tested. For React and Next.js the references cover Motion for React and React Three Fiber; those are built by your own bundler.
Can I use the scripts without an agent? Yes: the router, the checker and the capture tool are ordinary command-line programs.
Can it make a video? The capture tool makes a short loop of a scroll-through. For a finished, checked MP4, its sibling skill brief2mp4 is the tool.

What this guide rests on, and where its limits are.
Verified by running it
Every example passes check_site.mjs; the reports are in the repository. The numbers on the performance page are read from those reports when this guide is built.
Each stack's pattern is exercised by a smoke test in a real browser, including test pages for React Three Fiber, Rive, and a three.js model with post-processing.

Windows and Linux. Real phones and tablets. Safari and Firefox: the checks ran in Chrome 157 and 158 only.
Codex: the manifest is included, no run is recorded.
Screen readers: the structure is checked mechanically, not by listening.
React stacks inside a real bundled project: the React example and the React Three Fiber test page run from CDN modules.
Some style entries are thinner than others, and say so. Aurora, maximalism and editorial are documented as trends or traditions, not as defined web styles.
